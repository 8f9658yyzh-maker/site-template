# ホームページひな型 使い方説明書

## 1. これは何か（作った理由）

会社ごとに「中身（文章・写真・料金など）」だけを 1 つの設定ファイル（`site.json`）に書けば、
検索対策済みのホームページ一式（トップ・料金・流れ・スタッフ・ギャラリー・お知らせ・よくある質問・アクセス・予約フォーム・プライバシーポリシー）が自動で作られる仕組みです。

理由：業種が違っても、ホームページの骨組みはほぼ同じだからです。骨組みを 1 回だけ作っておけば、
2 社目以降は「中身の入れ替え」だけで済み、あなたの手間が小さくなります。

## 2. 入っているもの

| 場所 | 役割 |
|---|---|
| `build.mjs` | 設定ファイルからホームページを作る本体 |
| `validate.mjs` | 公開前の自動点検（リンク切れ・説明文の重複・画像の説明文など） |
| `genres.json` | 業種ごとの違い（見出しの言葉・ボタンの文言・フォームの種類・検索用の業種名） |
| `src/style.css` `src/main.js` | 見た目と、メニュー開閉などの小さな動き |
| `sites/sample` | 見本1：観光・体験（架空の会社） |
| `sites/sample-salon` | 見本2：美容室（架空の会社。2業種でも同じ仕組みで作れる証明） |
| `dist/` | 作った結果の出力先（公開するのはこの中の会社フォルダ） |

業種は `genres.json` に 6 種類あります：activity（観光・体験）／restaurant（飲食）／salon（美容室）／clinic（整体・治療院）／construction（工務店・塗装）／office（士業）。

## 3. 新しい会社を追加する手順

1. `sites/sample` フォルダを丸ごとコピーして、会社名のフォルダ（例：`sites/abc-shokudo`）にする
2. `site.json` を開き、中身を会社の情報に書き換える（項目の意味は 4 を参照）
3. `images/` に、その会社の写真を入れる（写真は必ずお客様から提供を受けたものを使う）
4. 作る：`node build.mjs sites/abc-shokudo`
5. 点検する：`node validate.mjs dist/abc-shokudo`（エラーが 0 になるまで直す）
6. 本番にする時だけ、`site.json` の `"isSample": true` を `false` に変える（理由は 5 を参照）

## 4. 更新（お知らせを足す・料金を変える）手順

お客様から文章をもらい、`site.json` の該当部分を書き換えて、手順 4→5 をやり直すだけです。
お知らせを足すなら、`"news"` の先頭に次の 1 件を足します。

```
{ "date": "2026-11-01", "title": "見出し", "body": "本文" }
```

## 5. site.json の主な項目

- `isSample`：true の間は「検索に出ない」設定になります。見本や作成途中のサイトが誤って検索に出ないための安全装置です
- `genre`：業種（上の 6 種類から選ぶ）
- `baseUrl`：公開するアドレス（例：`https://abc-shokudo.jp`）。検索用の正規アドレスやサイトマップに使われます
- `name` `tagline` `description`：会社名・ひとこと・説明文（説明文は検索結果に表示されやすい文章です）
- `address` `contact` `hours`：住所・電話・営業時間（検索用データにも自動で入ります）
- `pages`：作るページの選択。要らないページは配列から消すだけ
- `services` `flow` `staff` `gallery` `voices` `news` `columns` `faq` `access` `reserve`：各ページの中身
- `gallery` の各項目には `title` `body` `meta`（所要時間・費用・工期など）を付けられます。施工事例やスタイル写真の説明に使います
- `voices`：お客様の声。**掲載の許可をいただいたものだけ**を入れてください
- `columns`：読み物（コラム）。1記事が1ページになり、記事ごとに固有のアドレス（`/column/<slug>/`）と説明文を持ちます。`slug` は半角英数字とハイフンのみ
- `reserve.formAction`：予約フォームの送信先（空のままだと「受付準備中」と表示されます）

## 5-2. 業種別に載せると強い情報（調査の結果）

美容室・整体院・工務店について書かれた解説記事の内容（私が実サイトを見て確かめたものではありません）から、次の点が共通して挙げられていました。

- 料金は、最低価格だけでも載せる（料金が分からないと離脱されやすい）。未記入だと作成時に注意が出ます
- 施術者・スタッフの顔と人柄が分かるページ（美容室・整体院）
- 施工事例は、ビフォーアフターに加え、費用・工期・使った設備まで書く（工務店）
- 保証の内容、建設業許可や資格の表示（工務店）。`about.facts` に書けます
- 検索対策として、悩みに答える読み物（コラム）を増やす（整体院）
- 予約はフォームかLINEなど、電話以外の入口も用意する（美容室・整体院）

誇大に見える表現（「完治」「絶対」「No.1」など）は、点検で警告が出ます。裏付けを示せるか、公開前に必ず確認してください。

## 6. 作った仕組みの簡単な説明（関数）

`build.mjs` の中の主な部品です（データには触れません）。

- `layout()`：全ページ共通の枠（タイトル・説明文・正規アドレス・OGP・パンくず・メニュー・フッター・下の固定ボタン）を作る
- `pages.index / about / services ...`：ページごとの中身を作る。1 ページ 1 関数
- `jsonLd()`：検索エンジン向けの「この店はこういう店です」という構造化データを安全な形で出力する
- `esc()`：入力された文字の中の記号を無害化する（表示崩れ・不正な書き込みの防止）
- `FORM`：業種ごとの予約・相談フォームの項目一覧

## 7. 検索で上に出すために（名称と、確実に言えること・言えないこと）

- **SEO（エスイーオー／検索エンジン最適化）**：検索結果で見つけてもらいやすくするための取り組みの総称です。あなたが探している名称はこれです。
- **MEO（エムイーオー／マップエンジン最適化）**：Google マップ・「地域名＋業種」の検索で上に出すための取り組みを指す、日本の業界用語です。Google 自身の用語ではありません。お店のサイトでは、こちらの効果が大きいことが多いです。
- Google の公式ガイドには「ランキングがトップになるような秘訣はありません」と明記されています。つまり**順位の保証はできません**。変更の効果が出るまでには数週間かかることもあります。

このひな型で自動化済みのもの（Google 公式ガイドに沿った内容）：
ページごとに固有のタイトルと説明文／わかりやすい URL（`/services/` など）／正規アドレス／パンくず／画像の説明文の必須化／スマホ表示／サイトマップ／検索用の店舗データ（住所・電話・営業時間など）。

あなた（またはお客様）が公開後にやること：
1. **Google ビジネスプロフィールに店舗を登録し、オーナー確認を済ませる**（住所・電話・営業時間・写真）。地図検索の土台です
2. **Google Search Console にサイトを登録し、`sitemap.xml` を送る**（登録にはログインが必要です。お客様の Google アカウントで行うのが安全です）
3. 独自の文章と写真を載せる、休業日や料金を最新に保つ（公式ガイドが重視する点です）
4. 数週間後に Search Console で、どの言葉で表示されたかを確認する

※「生成 AI 向けの最適化」についても Google の公式ページがあることは確認しましたが、本文は読んでいません。内容は未確認です。

## 9. いまの限界（未完了のこと）

- 予約フォームの送信先は、見本では未設定です。受け皿と管理画面は `backend/` に作りました（手順は `backend/README.md`）。会社ごとの設置と、本物のGoogle上での動作確認が残っています
- 写真は仮の画像です。お客様の写真に差し替えてください

- 見本の文章は、点検でも警告として表示されます
- **調査の範囲について（正直な報告）**：「多数の有料実績サイトを見て作る」という依頼のうち、私が実際に確認できたのは、石垣島のNOAのサイト（3ページ）、制作会社の実績一覧の説明文、美容室・整体院・工務店の解説記事、Google公式資料です。個々の店の公式サイトを多数開いて構成を比べる作業は、十分にできていません。次の段階で、実在のサイトを業種ごとに数件ずつ開いて、足りない部分を追加します
- 他社の文章・写真は取り込んでいません（権利の問題が出るため）。構造（どんなページがあるか）だけを参考にしています


## SEO上の役割ごとの構成（seo-blueprint.json）
- `seo-blueprint.json` に、ページごとの「対策の種類・狙う検索の方向・書く内容・避けること」を定義しています。業種ごとの追加ルールは `genres.json` の `seoExtra`。
- 見本サイト（`isSample: true`）では、各ページ上部の【見本の説明】と `/_seo-plan/`（SEO構成図）にこの内容が出ます。本番サイトには出しません（確認したいときだけ `SEO_PLAN=1 node build.mjs sites/<社名>`）。
- 会社に文面をもらうときは、構成図の「ここに書く内容」をそのまま質問として渡せます。
- site.json の追加項目：`area`（地域名）、`intro`（トップ冒頭文）、`services.items[].slug/time/detail/related`（メニュー個別ページ）、`faq[].category`、`columns[].category/summary`、`staff[].qualifications/career`、`access.areaServed`。足りない項目は、作成時の【注意】に出ます。
- 検索回数・順位・クリック数への効果は測っていません。公開後に Search Console で確認します。
